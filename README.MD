# FireFly III integrator

A fast, responsive Node.js web app (light/dark themes) that will post data to a [FireFly III](https://www.firefly-iii.org/) instance. Runs as two containers: the app and PostgreSQL.

## Features

- Email + password registration and login (email format is regex-checked; there is no email ownership verification). OAuth is planned, not implemented.
- The first account created becomes the **global admin**.
- Global admins manage users and system settings (currently: *allow new registration*, off by default).
- Every user has Settings (password, FireFly III endpoint + API key, default tab) and an optional Profile.
- Tabs: **Post PDFs** (placeholder) and **Post file** (JSON/YAML editor; YAML is converted to JSON, validated against the account-transactions schema in `src/schemas/account-transactions.schema.json`, then each transaction is posted separately to the configured FireFly III endpoint). A results dialog summarizes successes and failures; invalid input is rejected before posting.
- Global notifications: success (green), warning (yellow), error (red), info (blue).
- Sessions: random 256-bit token in an `HttpOnly`, `Secure`, `SameSite=Lax` (`__Host-` prefixed) cookie; only a SHA-256 hash is stored server-side, with a sliding 30-day expiry.

## Posting transactions from a JSON/YAML file

1. In **Settings**, save your FireFly III endpoint and API key (see [Connecting to FireFly III](#connecting-to-firefly-iii)).
2. Open the **Post file** tab, choose JSON (or YAML), paste the content and post.
3. Review the results dialog: each transaction is posted independently, so one failure does not stop the others.

The file is an array of source accounts, each with its transactions. Every transaction requires `transaction_type`, which must be one of:

| `transaction_type` | Meaning | Created in FireFly III as |
|--------------------|---------|---------------------------|
| `transfer` | Move money between your own accounts (the destination must be an existing asset account). | Transfer |
| `payment` | Pay an external party (the destination is created automatically as an expense account if it does not exist). | Withdrawal |

```json
[
  {
    "source_account": "Checking",
    "currency": "USD",
    "transactions": [
      {
        "destination_account": "Savings",
        "transaction_type": "transfer",
        "amount": 250.00,
        "date": "2026-10-04",
        "description": "Monthly savings",
        "notes": "Optional"
      },
      {
        "destination_account": "Electric Company",
        "transaction_type": "payment",
        "amount": 82.40,
        "date": "2026-10-05",
        "description": "October electricity bill"
      }
    ]
  }
]
```

Fields per transaction: `destination_account`, `transaction_type`, `amount`, `date` (`YYYY-MM-DD`) and `description` are required; `notes` is optional; `foreign_amount` and `foreign_currency` are optional but must be given together. `source_account` and `currency` (applies to all its transactions) are required per account. Unknown properties and any other `transaction_type` value are rejected before anything is posted. The full schema is in [src/schemas/account-transactions.schema.json](src/schemas/account-transactions.schema.json).

## Installation

Requires Docker with Compose v2. The secrets are generated by you (or the installer) before the first start; the stack refuses to start without them. Replace `OWNER/REPO` below with this repository's path.

### Option 1: one-line installer

```bash
curl -fsSL https://raw.githubusercontent.com/OWNER/REPO/main/install.sh | sh
```

It creates `./firefly-iii-integrator/` with random secrets (existing ones are never overwritten), downloads `compose.yaml`, pulls the published image and starts the stack. Set `INSTALL_DIR` to change the folder, or `NO_START=1` to only prepare it. You can read the script first: [install.sh](install.sh).

### Option 2: manual, from the published image

```bash
mkdir -p firefly-iii-integrator/secrets firefly-iii-integrator/certs && cd firefly-iii-integrator
chmod 700 secrets
openssl rand -base64 36 | tr -d '\n' > secrets/db_password.txt   # database password
openssl rand -base64 48 | tr -d '\n' > secrets/app_secret.txt     # app secret; also encrypts stored FireFly III API keys, keep it safe and stable
chmod 644 secrets/*.txt   # must be readable by the non-root container users

curl -fsSL https://raw.githubusercontent.com/OWNER/REPO/main/compose.yaml -o compose.yaml
docker compose up -d
```

The `compose.yaml` that this downloads (no source checkout needed):

```yaml
# Secrets are read from ./secrets/*.txt, which YOU must create before the first start.
# See README.MD ("Installation"). Nothing secret is stored in this file or in the image.
services:
  db:
    image: postgres:16-alpine
    restart: unless-stopped
    environment:
      POSTGRES_USER: firefly_integrator
      POSTGRES_DB: firefly_integrator
      POSTGRES_PASSWORD_FILE: /run/secrets/db_password
    secrets:
      - db_password
    volumes:
      - db_data:/var/lib/postgresql/data
    networks:
      - backend
    security_opt:
      - no-new-privileges:true
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U firefly_integrator -d firefly_integrator"]
      interval: 5s
      timeout: 3s
      retries: 10

  app:
    image: ${APP_IMAGE:-pedrocsanchez/firefly-iii-integrator:latest}
    restart: unless-stopped
    depends_on:
      db:
        condition: service_healthy
    environment:
      DB_HOST: db
      DB_USER: firefly_integrator
      DB_NAME: firefly_integrator
      DB_PASSWORD_FILE: /run/secrets/db_password
      APP_SECRET_FILE: /run/secrets/app_secret
      # Set to "false" ONLY when serving over plain http (local testing).
      COOKIE_SECURE: ${COOKIE_SECURE:-true}
      TRUST_PROXY: ${TRUST_PROXY:-false}
    secrets:
      - db_password
      - app_secret
    ports:
      - "${APP_PORT:-3000}:3000"
    extra_hosts:
      - "host.docker.internal:host-gateway"
    volumes:
      - ./certs:/certs:ro
    networks:
      - backend
      - default
    read_only: true
    cap_drop: [ALL]
    security_opt:
      - no-new-privileges:true

networks:
  # The database is only reachable from the app, never from the host.
  backend:
    internal: true

secrets:
  db_password:
    file: ./secrets/db_password.txt
  app_secret:
    file: ./secrets/app_secret.txt

volumes:
  db_data:
```

To pin a version, set `APP_IMAGE`, e.g. `APP_IMAGE=pedrocsanchez/firefly-iii-integrator:0.2.0 docker compose up -d`. Update with `docker compose pull app && docker compose up -d app` (data in the `db_data` volume is kept).

### Option 3: build from source

Clone the repository, create the `secrets/` files as above and run `docker compose up -d --build` (`compose.override.yaml` makes Compose build locally instead of pulling).

Open <http://localhost:3000> and register: the first account is the admin.

Over plain HTTP (local testing) run with `COOKIE_SECURE=false docker compose up -d`. In production, put the app behind an HTTPS reverse proxy and set `TRUST_PROXY=true`. See [Configuration](#configuration) for what these do.

Passwords are passed as Docker secrets (files mounted at `/run/secrets`), never as environment values, and `secrets/` is git-ignored. The database sits on an internal network with no published port.

### Connecting to FireFly III

The endpoint saved in user Settings must be reachable **from inside the app container**. Enter only the base URL; the app appends `/api/v1/transactions`.

- If FireFly III runs directly on the Docker host, use `http://host.docker.internal:PORT` (the Compose service maps this name to the host gateway).
- If FireFly III runs in another Docker Compose project, `localhost` will not work. Attach the app and FireFly III services to a shared Docker network, then use FireFly III's service/container DNS name and its container port (for example `http://fireflyiii:8080`).
- For an HTTPS instance with a private or self-signed certificate, copy its certificate (or CA certificate) in PEM format (`.crt`, `.pem` or `.cer`) into the `certs/` folder. Nothing else is needed: every certificate in that folder is trusted automatically on the next post (no restart or rebuild). The folder is mounted read-only at `/certs`, TLS verification stays enabled, and the host browser's trust store is not shared with Docker. The certificate must list the IP address or DNS name used in your saved endpoint as a subject alternative name.

> Changing `db_password.txt` after the database was first initialised does not change the database user's password; change it inside PostgreSQL too. Losing/changing `app_secret.txt` makes stored API keys unreadable (users must re-enter them).

## Configuration

Set these as shell variables or in a `.env` file next to `compose.yaml`.

| Variable | Default | Description |
|---|---|---|
| `COOKIE_SECURE` | `true` | Marks the login session cookie as `Secure`, so browsers only send it over HTTPS and never over plain HTTP. The cookie is also `HttpOnly` and `SameSite=Lax`. Keep it `true` in production. Browsers drop `Secure` cookies on plain `http://` (except `localhost` in some browsers), so login will not persist; set it to `false` **only** for local testing over HTTP. |
| `TRUST_PROXY` | `false` | Set to `true` when the app runs behind a reverse proxy (nginx, Caddy, Traefik) that terminates HTTPS. The app then trusts the proxy's `X-Forwarded-*` headers for the client IP (used by login rate limiting) and the HTTPS scheme. Leave `false` if clients connect directly, otherwise they could spoof their IP. |
| `APP_PORT` | `3000` | Host port that exposes the app. |
| `APP_IMAGE` | `pedrocsanchez/firefly-iii-integrator:latest` | Image to run; set it to pin a version. |

## Versioning and releases

- The version lives in `src/package.json` and follows [SemVer](https://semver.org). Bump it with `cd src && npm version <patch|minor|major> --no-git-tag-version` in the PR that changes behavior.
- GitHub Actions (`.github/workflows/ci.yml`): every PR and branch push runs the tests, `npm audit` and a Docker build; the built image is stored as a workflow artifact (never pushed to a registry).
- Only pushes to `main` publish to Docker Hub, tagged `latest`, `<version>` and `sha-<commit>`.
- Repository setup for publishing: variable `DOCKERHUB_USERNAME` and secret `DOCKERHUB_TOKEN` (a Docker Hub access token with write scope). Update the default `APP_IMAGE` in `compose.yaml` if you publish under another name.

## Contributing and branch protection

Anyone can fork the repository and open a pull request. Only the maintainer can merge, because merging requires write access, which outside contributors do not have. Do not add collaborators with write access unless you want them to merge.

`main` must be protected so that nothing reaches it (and therefore Docker Hub) without a passing PR. Import [.github/rulesets/protect-main.json](.github/rulesets/protect-main.json) under *Settings → Rules → Rulesets → New ruleset → Import a ruleset*. It blocks direct pushes, force pushes and deletion of `main`, and requires a pull request with the `test` and `build` checks passing and up to date with `main`. Also set *Settings → Actions → General → Fork pull request workflows* to *Require approval for all outside collaborators*, so first-time contributors' workflows run only after you approve them. Fork PRs never receive the Docker Hub secrets.

## Security notes

- Each user chooses their own FireFly III endpoint, and the server calls it, so private-network addresses must be allowed (a typical FireFly III runs on your LAN). Redirects are not followed and non-JSON responses are never echoed back. Only give accounts to people you trust with network access from the app container, and keep registration disabled (the default) unless you need it.
- Report vulnerabilities privately through GitHub Security Advisories rather than public issues.
